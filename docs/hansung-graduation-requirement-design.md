# 한성대학교 졸업요건 자가점검 기능 설계서

## 1. 문서 목적

현재 Trekkey 백엔드와 프론트엔드 구조에 맞춰 한성대학교 학부생이 자신의 졸업요건 충족 여부를 자가점검하는 기능을 설계한다.

이 문서의 범위는 다음과 같다.

- 한성대학교 학교 공통 졸업요건
- 학번별 교양 최소 이수요건
- 전공 이수유형별 최소학점
- 일반·학사·외국인 편입 요건
- 조기졸업·학석사연계 조건
- 제1·제2트랙, 복수전공, 외국인 TOPIK, 학과별 졸업논문·작품의 확인 상태
- 현재 참가자 포털에 맞춘 화면과 데이터 흐름

DB와 API의 상세 계약은 다음 문서를 따른다.

- [한성대학교 졸업요건 ERD](./hansung-graduation-erd.md)
- [한성대학교 졸업요건 API·프론트 명세](./hansung-graduation-api-spec.md)

## 2. 제품 정의

학생이 학적정보와 누적성적을 입력하면 시스템은 요건별 상태를 계산한다.

```text
충족       SATISFIED
미충족     UNSATISFIED
확인 필요  UNKNOWN
해당 없음  NOT_APPLICABLE
```

전체 결과는 다음 세 상태만 사용한다.

```text
ELIGIBLE       모든 필수요건 충족
NOT_ELIGIBLE   하나 이상의 필수요건 미충족
INDETERMINATE  미충족은 없지만 확인 필요 요건 존재
```

이 결과는 한성대학교 종합정보시스템의 공식 졸업사정을 대체하지 않는다. 화면마다 기준일, 공식 출처, 면책문구를 표시한다.

## 3. 현재 코드와의 연결

### 3.1 백엔드

기존 구조를 그대로 따른다.

- `ORGANIZATION`: 한성대학교 식별
- `USER`: 로그인 학생과 학번·학교 연결
- `BaseEntity`: `created_at`, `updated_at`
- `AuthPrincipal`: 로그인 사용자 ID 사용
- `SuccessResponse<T>`: 모든 API 응답 래핑
- `ADMIN_AUDIT_LOG`: 정책 발행과 수동 검증 감사
- `SecurityConfig`: `/api/me/graduation/**`은 `PARTICIPANT`, `/api/admin/graduation/**`은 `ADMIN`

새 코드는 `com.api.trekkey.domain.graduation`에 둔다.

```text
domain/graduation
├── entity
├── repository
├── service
├── support
└── web
    ├── controller
    └── dto
```

졸업요건 판정은 Credential 발급과 분리한다. 대학 담당자가 공식 졸업 사실을 확인하기 전에는 블록체인 Credential을 발행하지 않는다.

### 3.2 프론트엔드

현재 프론트 `main`은 참가자 기능을 다음과 같이 구성한다.

- `routeConfig.js`의 `participantRoutes`
- `App.jsx`의 `useParticipantData`
- `ParticipantPortal.jsx`의 sidebar tab과 active view
- `backendApi.js`의 공통 인증·refresh request
- `ParticipantPortal.module.scss`의 portal panel 스타일

새 화면은 `/participant/graduation`으로 추가한다. `ParticipantPortal.jsx`가 이미 큰 파일이므로 실제 구현은 별도 컴포넌트로 분리한다.

```text
src/pages/participant/graduation/
├── GraduationRequirementsView.jsx
├── GraduationRequirementsView.module.scss
├── AcademicProfileForm.jsx
├── CourseRecordEditor.jsx
└── RequirementResultList.jsx

src/api/graduationApi.js
src/hooks/useGraduationData.js
```

## 4. 한성대학교 공식 기준 스냅샷

기준일은 2026-08-11이다. 정책을 DB에 발행할 때는 각 공식 페이지의 수집 시각과 본문 SHA-256을 함께 저장한다.

### 4.1 학교 공통

| 구분 | 기준 |
| --- | --- |
| 총 이수학점 | 16학번 이후 130학점, 15학번 이전 140학점 |
| 비교과 | 16학번 이후 800점, 15학번 이전 적용 없음 |
| 평점 | 총 평점평균 2.0 이상 |
| 학과·트랙 | 학번별 교양·전공 최소학점과 졸업종합시험·논문·작품 충족 |
| 트랙제 융합전공 | 제1트랙과 제2트랙 졸업요건 각각 충족 |
| 복수전공 | 제2전공 최소학점과 제2전공 졸업요건 충족 |
| 순수외국인 | 2012학년도 이후 신·편입생 TOPIK 4급 이상 |

등록요건은 일반 졸업사정의 경우 재학 상태에서 8학기차 이상으로 본다. 조기졸업·학석사연계는 별도 정책을 선택한다.

### 4.2 전공 이수유형 — 17학번 이후

| 이수유형 | 구성 | 전공기초·필수 세부기준 |
| --- | --- | --- |
| 융합전공 I | 1전공 39 + 2전공 39 = 78학점 | 각 전공 기초 3, 필수 15 포함 |
| 융합전공 II | 주전공 57 + 부전공 21 = 78학점 | 주전공 기초 3·필수 15, 부전공 기초 3·필수 12 포함 |
| 심화전공 | 한 전공 78학점 | 전공기초 3, 전공필수 15 포함 |
| 창의융합대학 소속 학과 | 학과 78학점 | 전공기초 3, 전공필수 21 포함 |
| 융합전공 I + 부전공 | 39 + 39 + 21 = 99학점 | 각 선택 단위의 세부 최소학점 적용 |
| 융합전공 I + Micro Degree | 39 + 39 + 9 = 87학점 | MD 9학점 적용 |

16학번 이전 학생은 공개 페이지의 구형 트랙제 합계만으로 과목 세부 분류를 확정하지 않고 수강신청 정보안내 책자 또는 학사운영팀 확인값을 사용한다.

### 4.3 교양 이수요건

#### 24학번 체계

- 교양 총 31학점 이상
- 교양필수 13학점
  - 사고와 표현 3
  - 영어커뮤니케이션 독해·작문 2
  - 영어커뮤니케이션 청취·회화 2
  - AI와 SW 기초 3
  - 한성 이마기난스 3
- 선택필수교양 15학점, 배분이수 4개 영역 이상
- 자율선택 3학점 이상
- 영어교과 면제자도 교양 총 31학점은 충족해야 함

2025학년도 이후 과목 대체와 상상력인재학부 예외는 해당 연도 교육과정표로 추가 검수한다. 공식 페이지에 명시되지 않은 학번 범위를 임의로 확대하지 않는다.

#### 19~23학번

- 교양 총 28학점 이상
- 사고와 표현 과목군 중 1개
- 영어커뮤니케이션 독해·작문 및 청취·회화
- `AI와 SW 기초` 또는 `문제해결을 위한 코딩 첫걸음` 중 1개
- 배분이수 3개 영역 이상

#### 17~18학번

- 교양 총 22학점 이상
- 교양필수 16학점
- 상상력 이노베이터, 사고와 표현 1·2, 영어커뮤니케이션 2과목, 코딩 첫걸음, 디자인 Thinking, 삶과 꿈

### 4.4 편입

| 입학유형 | 등록 | 전공/총학점 | 비교과 | GPA |
| --- | --- | --- | --- | --- |
| 일반편입, 16학번 이후 | 본교 4학기 이상 | 인정학점 포함 총 130 | 400 | 2.0 |
| 일반편입, 15학번 이전 | 본교 4학기 이상 | 인정학점 포함 총 140 | 없음 | 2.0 |
| 학사편입, 17학번 이후 | 본교 4학기 이상 | 본교 65, 전공 39(기초 3·필수 15), 자유 26 | 400 | 2.0 |
| 학사편입, 16학번 | 본교 4학기 이상 | 본교 65, 전공 39, 자유 26 | 400 | 2.0 |
| 학사편입, 15학번 이전 | 본교 4학기 이상 | 본교 70 | 없음 | 2.0 |

외국인편입은 편입 학년별 전공·자유선택·비교과 기준이 다르므로 별도 정책으로 둔다.

- 2학년 편입: 융합전공 I 78 + 자유선택 19, 비교과 600, 총 97
- 3학년 편입: 융합전공 I 78·비교과 400 또는 단일전공 39 + 자유 26·비교과 400
- 4학년 편입: 전공 33, 비교과 200

## 5. MVP 범위

### 포함

- 한성대학교 소속 참가자만 접근
- 신입학, 일반편입, 학사편입, 외국인편입
- 일반졸업, 조기졸업, 학석사연계
- 총학점, GPA, 등록학기, F 여부, 비교과점수
- 교양·전공 카테고리별 학점
- 제1·제2트랙, 부전공, 복수전공, MD
- 필수과목 체크
- TOPIK과 학과·트랙 졸업요건 확인 상태
- 결과 스냅샷과 공식 출처 표시

### 제외

- 한성대 포털 계정 수집 또는 자동 로그인
- 학교 포털 비공식 스크래핑
- PDF OCR 자동 확정
- 교직이수 세부 판정
- 학사 담당자 승인 없는 공식 졸업증명
- 졸업 Credential 자동 발급

성적표 업로드는 2차로 둔다. 1차 MVP는 학생이 종합정보시스템 누적성적 화면을 보며 직접 입력하거나 CSV 양식을 내려받아 올리는 방식이다.

## 6. 사용자 시나리오

### 최초 설정

1. 참가자 포털에서 `졸업요건` 선택
2. 한성대학교 소속 계정인지 확인
3. 학번, 입학유형, 졸업경로, 제1·제2트랙 입력
4. 시스템이 적용 정책을 미리 표시
5. 학생이 정책 적용 정보를 확인하고 저장

### 이수내역 입력

1. 총 등록학기, 총학점, GPA, 비교과점수 입력
2. 누적성적 과목을 코드·과목명·학점·성적·이수구분으로 입력
3. 과목을 전공 1/2, 교양필수, 선택필수교양 등에 매핑
4. TOPIK, 논문·작품, 학과승인 등 비교과 증빙 상태 입력
5. 저장 전 중복과목과 재수강을 확인

### 판정

1. `다시 검사` 실행
2. 서버가 정책 버전을 고정하고 판정
3. 전체 상태와 부족 항목 표시
4. 각 결과에서 공식 출처 열기
5. `UNKNOWN` 항목은 담당 학과 확인 안내

## 7. 판정 규칙

### 우선순위

```text
학적 프로필 선택
  → 입학유형 정책
  → 졸업경로 정책
  → 학번별 공통 정책
  → 교양 정책
  → 전공 이수유형 정책
  → 트랙·학과별 수동/자동 정책
```

### 총학점

- 일반편입은 전적대 인정학점을 포함한다.
- 학사편입은 본교 취득학점 기준을 별도로 평가한다.
- 중복수강·재수강은 최종 인정 학점만 합산한다.
- F, NP, 미취득 과목은 학점에 넣지 않는다.

### 전공학점

- 과목 하나를 여러 트랙에 중복 합산하지 않는다.
- 학교의 전공상호인정 결과가 있으면 학생 입력보다 우선한다.
- 전공상호인정이 미확정이면 관련 트랙 결과를 `UNKNOWN`으로 둔다.

### 수동 요건

다음은 검수된 구조화 규칙이 없으면 반드시 `UNKNOWN`이다.

- 학과·트랙 졸업논문·작품·시험
- 복수전공 제2전공 졸업요건
- 교직이수
- 교육과정 변경에 따른 이수인정
- 외부 프로그램 학점인정

학생이 `충족`으로 자가 입력해도 `SELF_REPORTED`이며 전체 결과는 `INDETERMINATE`다. 한성대 관리자 확인값이 `UNIVERSITY_VERIFIED`일 때만 자동 충족에 반영한다.

## 8. 프론트 화면 명세

### 8.1 라우트와 메뉴

`participantRoutes`에 다음을 추가한다.

```js
{ id: "graduation", path: "/participant/graduation", label: "졸업요건" }
```

sidebar 위치는 `활동 이력` 다음, `마이페이지` 이전으로 한다. 아이콘은 `GraduationCap`을 사용한다.

### 8.2 화면 구성

#### 헤더 요약

- `졸업 가능 예상`, `부족`, `확인 필요` 상태 배지
- 기준 정책: 예) `2024학번 · 융합전공 I`
- 마지막 검사 시각
- `다시 검사` 버튼

#### 진행 카드

- 총학점 `124 / 130`
- 교양 `28 / 31`
- 전공 1 `36 / 39`
- 전공 2 `39 / 39`
- 비교과 `720 / 800`
- GPA `3.42 / 2.0`

#### 요건 목록

- `미충족`을 먼저, `확인 필요`, `충족` 순서로 표시
- 항목마다 현재값, 기준값, 부족값, 해결 안내, 공식 출처 링크
- 필수과목은 과목명과 대체 인정 여부 표시

#### 학적 설정 drawer/modal

- 입학연도
- 입학유형
- 졸업경로
- 전공 이수유형
- 제1·제2트랙, 부전공, MD
- 외국인·교직·복수전공 여부

#### 이수내역 editor

- 데스크톱: 표
- 모바일: 과목 카드
- 코드, 과목명, 학점, 성적, 이수구분, 트랙 귀속
- 중복·재수강 경고

### 8.3 접근성

- 색만으로 상태를 표현하지 않고 텍스트와 아이콘 병행
- 진행률에 `aria-valuenow`, `aria-valuemin`, `aria-valuemax`
- 오류 요약과 필드 오류를 연결
- 표의 모바일 카드 변환에서도 헤더 의미 유지
- 공식 출처는 새 창 열림을 표시

```text
  규칙 타입별 순수 함수 판정

GraduationPolicyAdminService
  정책 초안·검수·발행·폐기
```

평가기에는 DB 접근을 넣지 않는다. 서비스가 프로필·과목·정책을 로딩한 뒤 불변 입력 객체를 만들어 evaluator에 전달한다.

## 10. 보안과 데이터 보호

- `USER.organization_id`가 한성대학교가 아니면 `GRADUATION_UNSUPPORTED_ORGANIZATION`
- 학생은 자신의 학적·성적·결과만 접근
- 관리자는 자기 organization 정책만 편집
- 정책 발행은 `ROOT_ADMIN` 또는 향후 `ACADEMIC_ADMIN`으로 제한 검토
- CSV 수식 주입 방지를 위해 `=`, `+`, `-`, `@` 시작 셀을 무해화
- 업로드 원본은 MVP에서 보관하지 않음
- 정책 발행·수동 승인·결과 재계산은 감사 로그 기록

## 11. 구현 단계

### 1단계 — 문서와 seed

- ERD와 API 계약 확정
- 한성대 공통·교양·전공·편입 정책 seed
- 공식 출처 해시 저장 방식 결정

### 2단계 — 백엔드

- 엔티티·migration·repository
- 정책 resolver와 evaluator
- 학생용 profile/course/evaluation API
- 단위·통합 테스트

### 3단계 — 프론트

- route와 sidebar
- `graduationApi.js`, `useGraduationData.js`
- 프로필·과목 입력과 결과 화면
- 모바일·접근성 검증

### 4단계 — 검수

- 한성대 학생 샘플 20건
- 학사 담당자의 종합정보시스템 판정과 비교
- 오차 원인 분류 후 정책 새 버전 발행

## 12. 완료 기준

- 17~24학번 신입학 기본 시나리오 판정
- 일반·학사·외국인 편입 분기 테스트
- 융합전공 I/II, 심화전공, 부전공/MD 테스트
- 총학점·GPA·비교과·교양·전공 부족량 정확히 계산
- 트랙별 자료가 없으면 합격으로 추정하지 않음
- 모든 결과가 정책 버전과 공식 출처를 가짐
- 현재 프론트 세션 복원과 access token refresh 흐름을 재사용
- 기존 대회·Credential 기능에 회귀 없음
