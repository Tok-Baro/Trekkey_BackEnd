# 공학경진대회 1차 예비 심사 보고서

## 1. 작품 제목

**Trekkey: Merkle Proof 기반 개인정보 보호형 대학 활동 Credential 발급·검증 플랫폼**

## 2. 작품 개요

생성형 AI의 확산으로 자기소개서와 포트폴리오 등 지원 문서를 작성하거나 수정하는 일은 쉬워졌지만, 문서에 적힌 활동이 실제로 수행되었는지와 현재도 유효한지를 판단하기는 더욱 어려워졌다. 개인은 실제 경험과 역량을 객관적인 근거로 제시하기 어렵고, 기업과 기관은 제출된 주장의 진위와 효력을 다시 확인해야 한다. 이는 취업·채용 과정의 정보 비대칭과 검증 비용을 키운다.

대학은 교과목 이수, 공모전 참여, 작품 제출, 수상, 자격증 승인 등 신뢰할 수 있는 원천 정보를 보유하고 있다. 그러나 이러한 기록은 여러 내부 시스템과 문서에 분산되어 있으며, 졸업 이후에는 외부에서 활용하거나 발급 기관에 직접 문의하지 않고 진위를 확인하기 어렵다.

Trekkey는 대학과 기관이 확인한 활동 사실을 검증 가능한 디지털 활동 증명(Credential)으로 발급하는 프로토콜이자, 이를 실제 대학 업무에 적용하는 플랫폼이다. 프로토콜은 활동 기록의 표준화, 기관 승인, 공개 정보 최소화, 해시 생성, 블록체인 앵커링, 외부 검증, 폐기·대체 절차를 정의한다. 현실의 활동 사실은 대학과 기관이 판단하고, Trekkey는 승인 당시 내용의 무결성과 현재 효력을 제3자가 검증할 수 있게 한다.

최신 통합 소스에는 대학 공모전 운영, 공모전 참여·작품·수상 Credential 발급, 학생 공개 활동 프로필, 외부 검증, 한성대학교 졸업요건 자가점검과 외부 증빙 2인 검수 MVP가 구현되어 있다. 학생은 특정 Credential 검증 링크를 선택해 제시하거나 자신의 공개 활동 프로필을 활성화·비활성화하고 링크를 교체할 수 있다. 외부 검증자는 별도 회원가입이나 블록체인 지갑 없이 발급 기관, 발급 시점, 내용 일치 여부와 현재 상태를 확인할 수 있다. 교과목·자격증·졸업 판정 결과를 새 Credential로 발급하는 기능은 후속 확장 범위다.

개인정보와 증빙 원문은 블록체인에 저장하지 않고 접근이 통제된 서버에 보관한다. Kaia 블록체인에는 원문·개인 식별정보 대신 여러 Credential을 묶은 Merkle Root, 발급자·스키마·배치 메타데이터와 폐기·대체 상태만 기록한다. 공개 활동 프로필은 UUID 기반 공개 ID를 사용하고 이메일·학번·자격증 번호를 제외한 요약 정보만 제공한다. 이 구조는 원문을 공개하지 않고도 제시된 내용이 발급 당시와 같은지, 그리고 현재도 유효한지를 나누어 검증하게 한다. 개별 Credential 검증 응답의 대상자 참조를 별도의 불변·대외용 opaque ID로 치환하는 작업은 공개 경계 고도화 항목으로 진행한다.

## 3. 작품의 주요 기능

### 1) Trekkey Credential 발급·검증 프로토콜

- 현재 대학이 확정한 공모전 참여, 작품 제출과 수상 기록을 표준 Credential 형식으로 변환한다. 교과목·자격증·졸업 판정 기록은 동일한 발급 계약으로 확장한다.
- 동일한 입력이 동일한 결과를 만들도록 기록을 정규화하고 SHA-256과 Keccak-256 기반 해시를 생성한다.
- 여러 Credential의 해시로 Merkle Tree를 구성하고, 개별 원문 대신 하나의 Merkle Root와 발급자·스키마·배치 메타데이터를 Kaia 블록체인에 기록한다.
- 기관은 Merkle 배치와 폐기·대체 상태 변경을 EIP-712로 승인한다. 개별 Credential은 Merkle Proof를 재계산해 온체인 Root와 일치하는지 확인하고, 발급자와 현재 상태를 함께 조회한다.
- 오발급되었거나 효력을 잃은 기록은 삭제하지 않고 폐기(`REVOKED`) 또는 대체(`SUPERSEDED`)로 전환해 변경 이력을 보존한다.

### 2) 대학 공모전 통합 관리

- 공모전 등록과 조회, 참가 신청, 팀 구성, 작품 제출의 전 과정을 관리한다.
- 심사위원 배정, 평가 입력, 순위 계산과 수상 확정 기능을 제공한다.
- 대학이 최종 확정한 참여·작품·수상 사실을 Credential로 발급한다.
- 참가자, 관리자, 심사위원과 최고 관리자의 역할·접근 권한을 구분한다.
- 주요 승인과 상태 변경을 감사 기록으로 보존해 업무 처리 과정을 추적한다.

### 3) 한성대학교 개인별 졸업요건 자가점검·외부 증빙 검수(MVP 구현)

- 입학연도, 입학유형, 졸업 경로, 전공 계획과 학업 단위를 반영해 적용할 졸업 정책을 선택한다.
- 학적 프로필, 성적표 PDF, 교과목·학점·비교과 기록을 기준으로 개인별 졸업요건을 자가점검한다.
- 전체 결과는 `충족 예상`·`미충족`·`판단 보류`, 개별 요건은 `충족`·`미충족`·`확인 필요`로 구분하고 부족한 학점과 추가 증빙을 안내한다.
- 학생이 자격증 등 외부 증빙을 제출하면 서로 다른 대학 관리자 2인이 수동 검수하고, 승인된 증빙을 졸업 비교과 기록에 연결한다.
- 공식 졸업 판정은 학사 시스템과 대학 승인의 영역으로 두며, 현재 MVP는 학교의 공식 졸업사정을 대체하지 않는다.
- 교과목·자격증·졸업 판정 결과를 취업·외부 제출용 Credential로 발급하는 기능은 후속 단계에서 연결한다.

### 4) 개인정보 보호형 외부 검증

- 사용자가 제공한 QR 또는 검증 코드로 Credential의 발급 정보, 내용 일치 여부와 현재 상태를 확인한다.
- 공개 활동 프로필 주소는 UUID 기반 공개 ID를 사용하고 이메일·학번·자격증 번호를 노출하지 않는다.
- 개인정보와 증빙 원문은 접근이 통제된 서버에 보관하고 블록체인에는 원문과 개인 식별정보를 기록하지 않는다.
- 외부 검증자는 별도 회원가입이나 블록체인 지갑 없이 일반 웹 브라우저에서 결과를 확인한다.
- 학생은 공개 활동 프로필을 비활성화하거나 공개 링크를 교체할 수 있다.
- 개별 Credential 검증 링크를 골라 제시할 수 있으며, 공개 활동 프로필 전체의 공개 여부와 링크를 관리할 수 있다. 프로필 내 활동·필드 단위 선택 공개는 후속 고도화 범위다.

## 4. 현재 개발 상황 및 개발 계획

본 작품은 기존에 개발한 대학 공모전 운영 시스템과 블록체인 Credential 기술을 통합·개선해 공학경진대회에 출품하는 것을 목표로 한다.

현재 학생·관리자 인증과 권한 관리, 공모전 등록 및 조회, 참가 신청, 팀 관리, 작품 제출, 심사위원 배정, 평가와 수상 확정까지의 대회 운영 기능이 구현되어 있다. Credential 정규화와 해시 생성, Merkle Tree 및 Proof 생성, Merkle 배치·상태 변경에 대한 EIP-712 기관 승인, Kaia Kairos 테스트넷 스마트 컨트랙트 앵커링, 폐기·대체 상태 관리도 구현했다. 외부 사용자가 QR 또는 검증 코드로 Credential의 발급 정보와 현재 효력을 확인하는 공개 검증 화면, 학생 공개 활동 프로필, 공개 링크 비활성화·교체 기능도 구현된 상태이다.

최신 통합 소스에는 한성대학교 학적 프로필, 성적표 PDF 가져오기, 교과·학점·비교과 기록 기반 졸업요건 자가점검, 외부 증빙 제출과 서로 다른 관리자 2인의 수동 검수, 승인된 증빙을 졸업 비교과 기록으로 연결하는 흐름도 구현했다. 다만 전체 학과·트랙 공식 정책과 학적 상태 정보가 완비되지 않아 현재 결과는 자가점검 MVP이며, 학교의 공식 졸업사정을 대체하지 않는다. 또한 공모전 Credential을 졸업 비교과 근거로 가져오는 흐름은 구현했지만, 졸업 판정·교과목·자격증 기록을 새 Credential로 발급하는 파이프라인은 후속 범위다.

프론트엔드는 React, 백엔드는 Spring Boot와 MySQL, 스마트 컨트랙트는 Solidity로 개발했으며 web3j를 통해 Kaia 블록체인과 연동했다. 데이터베이스 처리와 블록체인 트랜잭션 사이의 불일치에 대응하기 위해 Transactional Outbox, 멱등 처리, 재시도와 온체인 재조회(read-back) 구조를 적용했다.

2026년 7월 21일 대회 관리 실기동 검증에서 인증·권한·공모전 운영·보안 관련 HTTP 시나리오 28개를 최종 통과했고, 단위·컨트롤러 회귀 테스트 109개를 통과했다. 최신 통합 소스 QA에서는 백엔드 테스트 664개 중 환경 조건부 27개를 건너뛰었고 실패는 0개였다. 프론트엔드 테스트 19개와 Solidity 테스트 12개도 통과했다. 이 수치는 각 검증 시점과 범위의 결과이며, 전체 학과·트랙 공식 정책과 학사 시스템 연동 완료를 의미하지는 않는다.

### 작업 중인 개선 사항

- 전체 학과·트랙·입학유형별 공식 졸업 정책과 학적 상태 데이터 완비
- 자격증 발급기관 registry, 공식 기관 API·전자서명 연동과 도메인 allowlist 구축
- 교과목·자격증·졸업 판정 결과의 Credential 발급 adapter 및 공모전 Credential과의 통합 검증
- 활동·필드 단위 선택 공개와 개별 Credential 대상자 참조의 불변·대외용 opaque ID 전환
- 증빙 파일 악성코드 검사, OCR, 만료·철회 변경의 자동 재평가
- 기업용 검증 대시보드와 외부 시스템 연동 API 개발
- Credential 발급, Merkle 배치, 블록체인 기록과 외부 검증 단계별 처리 시간·가스비·장애 복구 시간 측정
- 모바일 QR 사용성, 접근 통제, 모니터링, 백업, 통합 시연 환경과 Mainnet 전환 요건 검토
