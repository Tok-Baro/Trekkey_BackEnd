# 한성대학교 실제 공지·서류 기반 졸업요건 Gap QA

## 1. 범위와 결론

- 점검일: 2026-08-18
- 대상: Trekkey 한성대 졸업 판정 엔진, 외부 증빙 제출·2인 관리자 검수, 참가자/관리자 화면
- 원칙: 공개된 한성대학교 공식 자료만 사용하고 실제 학생의 성적표·자격증 등 개인정보 문서는 사용하지 않았다.
- 결론: 공통 학점·편입·교양·전공 구조와 외부 증빙 연결은 동작하지만, 현재 데이터만으로는 한성대 전체 학생에게 `ELIGIBLE`을 확정하면 안 된다. 학적 상태와 학과·트랙별 발행 정책이 없는 경우 반드시 `INDETERMINATE`로 남겨야 한다.

## 4. 실제 서류 검증 3-cycle

### Cycle 1 — 원문·정책 대조

- 학교 공통, 전공, 교양, 편입, 졸업사정, 컴퓨터공학부, AI응용, 융합보안, 학석사연계 자료를 교차 확인했다.
- 공통 설계 문서와 실제 실행 가능한 규칙을 분리했다.
- 결과: 학적 상태와 학과별 발행 정책이 없으면 공식 수준 판정을 낼 수 없음을 확인했다.

### Cycle 2 — 실제 PDF·multipart 경계

- 한성대 공식 4쪽 PDF를 다운로드해 MIME 주장 대신 실제 PDF parser로 열고 페이지 존재 여부를 검사했다.
- 같은 검사에서 헤더만 있는 가짜 PDF/JPEG/PNG가 거절되는 회귀 테스트를 추가했다.
- 프론트와 컨트롤러 계약을 `files` 반복 multipart part로 바꿔 2파일 bundle POST를 검증했다. 기존 단일 `file` part는 하위 호환으로 유지한다.

### Cycle 3 — 검수·졸업판정 회귀

- 서로 다른 관리자 2인 합의, 동일 관리자 재검수 차단, 불일치 `INCONCLUSIVE`를 재검증했다.
- 승인된 `DOCUMENT_VERIFIED/L2` 자료만 규칙에 반영하며, 만료 문서는 다시 `UNKNOWN`으로 떨어지는 테스트를 추가했다.
- 백엔드 전체 662개 중 실패 0(외부 MySQL 25개와 환경변수 기반 실제파일 1개 조건부 skip), 실제 한성대 PDF smoke 별도 통과, 프론트 14개 통과 및 production build 성공을 확인했다.

## 5. 운영 판정 기준

현 상태에서 화면의 `ELIGIBLE`은 다음 조건을 모두 만족할 때만 노출해야 한다.

1. 해당 학번·입학유형·졸업경로의 공통/교양/전공 정책이 모두 발행돼 있다.
2. 선택한 모든 1·2트랙·복수전공에 `UNIT_GRADUATION` 정책이 있다.
3. 학적 상태가 졸업심사 가능한 상태로 학교 담당자에게 확인됐다.
4. 논문·작품·자격증·TOPIK·교직 등 필요한 외부 항목이 유효한 증빙과 학교 확인을 갖는다.
5. 졸업사정 결과 확인 전까지 문구는 계속 “자가점검 예상”이어야 한다.

이 중 하나라도 데이터가 없으면 `INDETERMINATE`가 안전한 결과다.
